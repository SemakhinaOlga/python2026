# Вопрос 1. Тема: Сложные запросы
  
**1. Какой оператор используется для объединения двух таблиц в SQL?**
  
Варианты ответов:
1) COMBINE
2) ✅ JOIN
3) UNION
4) MERGE
  
### ИИ анализ
Оператор `JOIN` является основным в SQL для объединения строк из двух или более таблиц на основе связанного столбца между ними.  Варианты `COMBINE` и `MERGE` не являются стандартными SQL-операторами для этой цели, а `UNION` используется для сложения наборов строк, а не для их объединения по условию.  Вы правильно выбрали верный вариант, демонстрируя понимание базового синтаксиса SQL.  
  
# Вопрос 2. Тема: Сложные запросы
  
**2. Как объединить таблицы Customers и Orders по полю CustomerID и выбрать все строки из таблицы Customers, даже если нет соответствующих записей в таблице Orders?**
  
Варианты ответов:
1) SELECT * FROM Customers RIGHT JOIN Orders ON Customers.CustomerID = Orders.CustomerID
2) ❌ SELECT * FROM Customers FULL JOIN Orders ON Customers.CustomerID = Orders.CustomerID
3) SELECT * FROM Customers INNER JOIN Orders ON Customers.CustomerID = Orders.CustomerID
4) SELECT * FROM Customers LEFT JOIN Orders ON Customers.CustomerID = Orders.CustomerID
  
### ИИ анализ
Для задачи "все строки из таблицы Customers, даже если нет соответствующих записей" требуется `LEFT JOIN`.  `FULL JOIN` (ваш выбор) вернёт все строки из обеих таблиц, что не соответствует условию.  `INNER JOIN` вернёт только совпадающие строки, а `RIGHT JOIN` — все строки из таблицы Orders.  Обратите внимание на направление соединения: `LEFT JOIN` сохраняет строки из таблицы, указанной слева (Customers).  
  
# Вопрос 3. Тема: Сложные запросы
  
**3. Что вернёт запрос `SELECT Customers.Name, Orders.OrderID FROM Customers LEFT JOIN Orders ON Customers.CustomerID = Orders.CustomerID;`, если в таблице Customers есть клиенты без заказов?**
  
Варианты ответов:
1) ❌ Запрос вернёт только клиентов с заказами
2) Запрос не вернёт результатов
3) Запрос вернёт только заказы, без клиентов
4) Запрос вернёт всех клиентов (включая тех, у кого нет заказов) с пустыми значениями для OrderID
  
### ИИ анализ
`LEFT JOIN` гарантирует, что все строки из левой таблицы (Customers) будут включены в результат.  Для клиентов, у которых нет совпадающих заказов, поля из правой таблицы (Orders.OrderID) будут содержать значения NULL.  Ваш выбор (только клиенты с заказами) описывает поведение `INNER JOIN`.  Важно запомнить, что `LEFT JOIN` используется именно для включения всех записей из основной таблицы, даже без соответствий.  
  
# Вопрос 4. Тема: Сложные запросы
  
**4. Какой результат вернёт следующий SQL-запрос?**

```
SELECT Name FROM Customers
UNION
SELECT Name FROM Suppliers;
```
  
Варианты ответов:
1) Вернёт только совпадающие значения из обеих таблиц
2) ✅ Вернёт только уникальные имена из таблиц Customers и Suppliers
3) Объединит результаты, но добавит NULL вместо отсутствующих значений
4) Объединит результаты обеих таблиц, включая дубликаты
  
### ИИ анализ
Оператор `UNION` по умолчанию объединяет результаты двух `SELECT`-запросов и автоматически удаляет дублирующиеся строки из итогового набора.  Ваш ответ верен: будут возвращены все уникальные имена из обеих таблиц.  Вариант "включая дубликаты" соответствует оператору `UNION ALL`, а "только совпадающие" — оператору `INTERSECT`.  
  
# Вопрос 5. Тема: Сложные запросы
  
**5. Какой результат вернёт следующий SQL-запрос?**

```
SELECT ProductName FROM Products
EXCEPT
SELECT ProductName FROM DiscontinuedProducts;
```
  
Варианты ответов:
1) Вернёт только товары, которые присутствуют в обеих таблицах
2) Вернёт список всех товаров, включая устаревшие
3) Вернёт только устаревшие товары
4) ✅ Вернёт товары, которые есть в Products, но отсутствуют в DiscontinuedProducts
  
### ИИ анализ
Оператор `EXCEPT` возвращает строки из первого набора данных, которые отсутствуют во втором.  Таким образом, запрос вернёт имена продуктов, которые есть в таблице Products, но которых нет в таблице DiscontinuedProducts, то есть текущие, не снятые с производства товары.  Вы правильно определили логику работы этого оператора.
